### Giải thích tại sao AI thường bỏ sót 5 Test Case này (Bước 2 - Extend)
1. **TC_CHK_036 (SQLi Boolean trong trường số):** AI thường chỉ sinh SQLi vào các trường chuỗi (`shipping_address`, `email`) mà quên mất việc truyền chuỗi độc hại vào trường quy định là kiểu số (`total_amount`). Kẻ tấn công có thể lợi dụng lỗ hổng Parse Int của server để chèn SQLi.
2. **TC_CHK_037 (Số mũ khoa học):** Các công cụ AI cơ bản khi tạo test case Domain Partition thường chỉ nghĩ đến số nguyên, số thập phân, số âm, số quá lớn, nhưng lại bỏ quên chuẩn JSON cho phép định dạng `2e5` (tương đương 200000). Nhiều backend parser sẽ bị crash khi gặp dạng này.
3. **TC_CHK_038 (Header Spoofing):** AI khi đọc đặc tả API chỉ tập trung vào Payload (Body) mà ít khi test khả năng giả mạo IP bằng các header như `X-Forwarded-For` hoặc `X-Original-URL`.
4. **TC_CHK_039 (Parameter Pollution):** Đây là kỹ thuật hack nâng cao (Gửi trùng 2 key JSON). AI ít khi tự động sinh test case này trừ khi được train chuyên sâu về Security.
5. **TC_CHK_040 (Race Condition / Chained State Transition):** AI thường chỉ test 1 hành động độc lập (ví dụ đặt hàng xong rồi thôi). Nó ít khi test luồng kết hợp: Đặt hàng xong hủy ngay lập tức trong tích tắc để xem luồng rollback có bị lỗi hay không.
